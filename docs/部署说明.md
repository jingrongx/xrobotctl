# 部署说明

## 前提

1. **设备已 root**：小方头用 CVE-2020-0069 + RootKeeper 方案（见「小方头机器人超级工具箱」）。
2. **USB 调试已开**，adb 能连上。
3. **平台签名**：`com.ubtrobot.permission.ROBOT` 是 signature 级权限，中枢 APK 必须用平台 key 签名才能拿到底盘控制。

## 平台签名

把 AOSP platform key 放到 `keys/`（这两个文件已在 `.gitignore`，不会进仓库）：

```
keys/platform.pk8
keys/platform.x509.pem
```

小方头 ROM 用的是 AOSP test-keys，直接用 AOSP 的默认 platform key 即可。没有签名文件时 `build_hub.sh` 会退回 debug 签名——**能装但控制不了底盘**。

## SDK dex

中枢通过 `DexClassLoader` 加载 UBTECH SDK：`/data/local/tmp/visbot1.dex`。这是从设备 ROM 的 vdex 反优化而来，有版权敏感性，**不随仓库分发**。

- 设备已 root 过的，`/data/local/tmp/visbot1.dex` 通常已就位。
- 需重新生成时，用 dequickifier 工具从 `/system/framework/` 或 `/data/dalvik-cache/` 的 vdex 提取（历史流程在超级工具箱的 `ROOT-README.md`）。
- 部署脚本会 `chmod 666` 确保中枢可读。

## 构建与安装

```bash
./tools/build_client.sh                 # 客户端 jar
./tools/build_hub.sh                    # 中枢 APK（平台签名）
./tools/deploy.sh [设备序列号]          # 一键部署并自检
```

`deploy.sh` 会：装 APK（覆盖旧版，包名保持 `com.visbot.robotctl`）→ 启动中枢进程 → 打印 `ping` / `capabilities` 自检结果。

## 常驻要点（重要）

- **不要 force-stop 中枢进程**。每次 force-stop 会导致 UBTECH 的竞争会话重建，转向指令被静默丢弃（实测现象：下发 90° 只转 45°）。
- 保持电池白名单：`dumpsys deviceidle whitelist +com.visbot.robotctl`（超级工具箱已做）。
- 开机自启与自愈由 RootKeeper 负责，无需手动干预。

## 验证

```bash
adb shell content call --uri content://com.xrobot.hub.api --method ping
adb shell content call --uri content://com.xrobot.hub.api --method capabilities
adb shell content call --uri content://com.xrobot.hub.api --method move --arg "30,8"
```

第一条应返回 `ok=true` 且 `ready=true`。
