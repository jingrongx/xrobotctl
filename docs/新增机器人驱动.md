# 新增机器人驱动

中枢不关心机器人细节，只认 `RobotDriver` 接口。接入新机型三步：

## 1. 实现驱动

在 `hub/src/com/xrobot/hub/driver/` 新建，例如 `DogDriver.java`：

```java
public final class DogDriver implements RobotDriver {
    @Override public String id() { return "dog"; }
    @Override public String displayName() { return "四足机器狗"; }
    @Override public String[] capabilities() {
        return new String[]{"move", "turn", "status"};   // 没有头部/视觉就不写
    }
    @Override public boolean isReady() { /* 底层 SDK 是否初始化 */ }
    @Override public void move(float dist, float speed) { /* 调你的 SDK */ }
    @Override public void turn(float angle, float speed) { /* ... */ }
    @Override public void turnRaw(float angle, float speed) { /* ... */ }
    @Override public void head(float angle, float speed) { /* 不支持可留空 */ }
    @Override public void stop() { /* ... */ }
    @Override public String status() { return "..."; }
    @Override public String info() { return "..."; }
    @Override public void startVision(Context c, String color, boolean dry) { }
    @Override public void stopVision() { }
}
```

要点：
- `capabilities()` 决定中枢是否放行该命令。**没写的能力，中枢返回明确错误，不会调用你的空实现**。
- 动作方法非阻塞下发即可，抛异常会被中枢捕获并封装成 `ok=false`。
- 单位：距离厘米、角度度；速度单位各自定义，在 `info()` 里写清楚。

## 2. 注册

在 `HubApp.onCreate()` 里加一行：

```java
DriverRegistry.register(new DogDriver());
```

## 3. 构建部署

```bash
./tools/build_hub.sh
./tools/deploy.sh
```

调用方**一行都不用改**——它们通过 `capabilities()` 自动知道多了一个机型的能力。

## 多驱动选择

`DriverRegistry.active()` 默认取第一个 `isReady()` 的驱动。若同机上多个驱动都就绪，按注册顺序（优先级）取第一个。将来如需按机型自动选择，可在 `HubApp` 里根据 `Build.MODEL` / `getprop` 条件注册对应驱动即可。

## 依赖的底层 SDK

版权敏感的 SDK（如小方头的反优化 dex）不要提交仓库。参考 `VisbotDriver` 的做法：底层代码放在 `hub/src/com/visbot/`，运行时 dex 从设备提取（见 [部署说明](部署说明.md)）。
