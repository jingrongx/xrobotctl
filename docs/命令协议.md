# 命令协议

中枢 Provider 同时监听两个 authority，协议完全一致：

- **新**：`content://com.xrobot.hub.api`（推荐）
- **旧**：`content://com.visbot.robotctl.api`（兼容老调用方）

## 命令行格式

```bash
adb shell content call --uri content://com.xrobot.hub.api \
    --method <方法> --arg "<参数>" [--extra arg1:f:<值> --extra arg2:f:<值>]
```

`--arg` 用 `"数值,数值"` 字符串，对应 `arg1`、`arg2`；也可用 `--extra` 传 float。

## 方法一览

| method | arg / extras | 返回 | 说明 |
|---|---|---|---|
| `ping` | — | `driver`,`name`,`ready`,`drivers` | 探活 + 当前驱动 |
| `capabilities` | — | `capabilities`[] | 当前驱动能力 |
| `status` | — | `status` | 状态文本 |
| `info` | — | `info`,`name` | 设备参数 |
| `move` | `距离,速度` | `ok` | 距离恒正，负速度=后退 |
| `turn` | `角度,速度` | `ok` | 正=左，负=右 |
| `rawTurn` | `角度,速度` | `ok` | 原始转向（视觉闭环/标定用） |
| `head` | `角度,速度` | `ok` | −23~+25° |
| `stop` | — | `ok` | 急停 + 停视觉 |
| `goto` | `颜色` | `ok` | 视觉追踪并走过去 |
| `detect` | `颜色` | `ok` | 只检测不驱动 |

所有返回都含 `ok`(boolean)；失败时 `msg`(String) 给出原因（未知命令 / 能力不支持 / 异常摘要）。

## 能力检查

驱动在 `capabilities()` 里声明能力。调用未声明的能力时中枢返回：

```
ok=false, msg="驱动 xxx 不支持能力: head"
```

不会调用底层空实现，也不会崩溃。这是多机器人兼容的核心机制。

## 示例

```bash
adb shell content call --uri content://com.xrobot.hub.api --method ping
adb shell content call --uri content://com.xrobot.hub.api --method capabilities
adb shell content call --uri content://com.xrobot.hub.api --method move  --arg "30,8"
adb shell content call --uri content://com.xrobot.hub.api --method move  --arg "30,-8"
adb shell content call --uri content://com.xrobot.hub.api --method turn  --arg "90,60"
adb shell content call --uri content://com.xrobot.hub.api --method head  --arg "25,15"
adb shell content call --uri content://com.xrobot.hub.api --method stop
adb shell content call --uri content://com.xrobot.hub.api --method goto  --arg "red"
```

## Java 里直接用（不通过客户端 SDK）

```java
Uri uri = Uri.parse("content://com.xrobot.hub.api");
Bundle in = new Bundle();
in.putFloat("arg1", 30f);   // 距离
in.putFloat("arg2", 8f);    // 速度
Bundle out = getContentResolver().call(uri, "move", null, in);
boolean ok = out.getBoolean("ok");
```

建议直接用 `XRobot` 客户端（见 [客户端集成指南](客户端集成.md)），它封装了这些细节。
