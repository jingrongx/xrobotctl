# 自动发版说明

推送到 `main` 分支即触发 GitHub Actions，自动完成：算版本 → 生成更新日志 → 构建签名 APK → 创建 Release → 回提交日志。无需任何手动操作。

## 触发方式

| 方式 | 说明 |
|---|---|
| `git push origin main` | 主分支代码推送，自动发版（日常主要方式） |
| Actions 页面「Run workflow」 | 手动触发一次发版 |

只改 `CHANGELOG.md` 不会触发（该文件由流程自己维护，防止循环）。改文档、示例、代码都会发版。

## 版本规则

- 版本号来自 git tag，格式 `v主.次.补`
- 首次发版（仓库无 tag）：`v1.0.0`
- 之后每次：取最新 tag 的 patch +1（`v1.0.0` → `v1.0.1` → `v1.0.2` …）
- 版本号无需手动维护，`tools/gen_changelog.py --next-only` 现算

需要大版本/次版本升级（如 `v2.0.0`）时，手动打一个 tag 推上去即可，下次会自动在此基础上 +1：
```bash
git tag v2.0.0 && git push origin v2.0.0
```

## 更新日志

- 每次发版汇总「上个 tag .. 当前 HEAD」的提交，按 新增 / 修复 / 文档 / 重构 / 发版 / 其他 分类
- 结果写入根目录 `CHANGELOG.md`（新版本置顶，保留历史），并作为本次 Release Notes
- 由 `tools/gen_changelog.py` 生成，提交信息用中文也能正确归类；bot 自己的回提交会被过滤，不会自我繁殖

## 产物

Release 附带 `XRobotHub-<版本>.apk`，已用平台签名，下载后直接安装即可控制底盘。

构建在 Linux runner 上用 `tools/build_hub_ci.sh` 完成（不依赖 Windows/Android Studio）：

| 环节 | 工具 |
|---|---|
| manifest | aapt2 |
| 编译 | javac `--release 8` |
| dex | d8 |
| 打包对齐 | python + zipalign |
| 签名 | apksigner（platform key） |

## 一次性配置：签名密钥

平台签名是硬性要求（`com.ubtrobot.permission.ROBOT` 是 signature 级权限），但私钥**绝不能入库**（`.gitignore` 已排除 `keys/*`）。走 GitHub Secrets：

```bash
cd 仓库根目录
# 在 Settings → Secrets and variables → Actions → New repository secret 中，
# 分别创建下面两个 Secret，值用以下命令生成（整行复制）：
base64 -w0 keys/platform.pk8      # → PLATFORM_PK8_B64
base64 -w0 keys/platform.x509.pem # → PLATFORM_X509_B64
```

- macOS 用 `base64 -i keys/platform.pk8 | tr -d '\n'`
- 不配这两个 Secret 也能发版，但 APK 是 debug 签名、拿不到 ROBOT 权限（流程会打印 warning）
- 换 ROM / 换机型时替换这两个 Secret 即可，无需改代码

## 权限与并发

- 工作流用 `GITHUB_TOKEN`，需 `contents: write`（已在工作流中声明），用于建 Release、打 tag、回提交
- `concurrency` 保证同一分支同时只有一个发版在跑，避免版本/日志错乱
- 回提交带 `[skip ci]`，且 GITHUB_TOKEN 的 push 默认不触发新工作流，双重防止循环

## 查看状态

```bash
gh run list --repo jingrongx/xrobotctl          # 发版历史
gh run view --repo jingrongx/xrobotctl --log    # 某次日志
gh release list --repo jingrongx/xrobotctl      # 所有版本
gh release download <版本> --repo jingrongx/xrobotctl  # 下载 APK
```
